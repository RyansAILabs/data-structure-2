Pilhas (LIFO)

Pilha é a estrutura do “último que entra, primeiro que sai”. É uma lista com regra de acesso: você só mexe no topo. Com essa restrição simples, resolve três clássicos da prova: parênteses balanceados, avaliação de expressão pós-fixa e conversão de infixa para pós-fixa.

~30 min de estudo LIFO pós-fixa código Java testado

01 O modelo LIFO

LIFO = Last In, First Out. O único elemento visível é o topo. push empilha no topo; pop desempilha do topo; peek consulta o topo sem remover. O fundo da pilha fica inacessível até os de cima saírem.

03 Como implementar

Com lista encadeada (versão do professor)

A pilha é uma especialização da lista: push é inserir no fim, pop é remover do fim e peek é consultar o fim. Com descritor, as três operações são O(1).

Os arquivos linkados nesta página são cópias fiéis do repositório do professor; os blocos de código mostram os mesmos métodos com comentários do guia.

Stack.java — completa
public class Stack<T> extends LinkedLinearList<T> {

    public Stack(int capacity) {
        super(capacity);
    }

    public boolean push(T value) {
        return add(value);              // insere no fim da lista
    }

    @Override
    public T pop() throws OperationFailed {
        return removeLast();            // remove do fim = topo
    }

    @Override
    public void display() {
        super.display();
    }

    public T peek() throws OperationFailed {
        if (isEmpty()) {
            throw new OperationFailed();
        }
        return get(size() - 1);         // último elemento
    }
}

Com vetor (top = índice do topo)

A pilha com vetor (SequentialStack.java) é um complemento do guia; o repositório do professor implementa a pilha sobre a lista encadeada com descritor.

O vetor guarda os elementos de baixo para cima. top começa em −1 (vazia); ao dar push, incrementa e grava; ao dar pop, lê data[top] e decrementa. É a implementação mais provável de aparecer em questão de “complete o código”.

SequentialStack.java — push e pop
public boolean push(T value) {
    if (isFull()) {          // top == data.length - 1
        return false;
    }
    data[++top] = value;     // primeiro incrementa, depois grava
    return true;
}

public T pop() throws OperationFailed {
    if (isEmpty()) {         // top == -1
        throw new OperationFailed();
    }
    T value = (T) data[top];
    data[top] = null;
    top--;
    return value;
}

public T peek() throws OperationFailed {
    if (isEmpty()) {
        throw new OperationFailed();
    }
    return (T) data[top];
}
⚠️
Vetor: cuidado com a ordem

No push, use data[++top] = value (pré-incremento). Se usar data[top++], grava na posição antiga e deixa o topo apontando para a posição errada. No pop, leia antes de decrementar.

04 Aplicação 1: parênteses balanceados

Cada fechamento deve casar com o último símbolo aberto — comportamento LIFO. Ao encontrar uma abertura, empilhe. Ao encontrar um fechamento, desempilhe e verifique se combina. No fim, a pilha deve estar vazia.

A implementação abaixo é um complemento do guia: o repositório do professor não traz esse algoritmo pronto, mas ele é o exemplo clássico de uso de pilha.

BalancedParentheses.java
public static boolean isBalanced(String expression) throws OperationFailed {
    Stack<Character> stack = new Stack<>(expression.length() + 1);

    for (int i = 0; i < expression.length(); i++) {
        char c = expression.charAt(i);
        if (c == '(' || c == '[' || c == '{') {
            stack.push(c);
        } else if (c == ')' || c == ']' || c == '}') {
            if (stack.isEmpty()) {
                return false;              // fechou sem abrir
            }
            char top = stack.pop();
            if (!matches(top, c)) {
                return false;              // abriu um, fechou outro
            }
        }
    }
    return stack.isEmpty();                // sobrou abertura? falso
}

05 Aplicação 2: avaliar pós-fixa

Na notação pós-fixa (polonesa reversa), o operador vem depois dos operandos: 6 2 3 * - significa 6 − (2 × 3). A regra é simples: número → empilha; operador → desempilha dois, aplica e empilha o resultado. No fim, sobra um valor.

ℹ️
O que está no repositório

O exemplo PostFixed.java do professor é uma versão mínima: recebe uma pilha com exatamente três caracteres (dois operandos e um operador) e trata apenas + e −. O PostfixEvaluator.java deste guia generaliza a mesma ideia para expressões com vários tokens e os quatro operadores. Para a prova, use a regra geral — e, se o enunciado pedir o código do professor, respeite a limitação de três caracteres.

🚨
A ordem dos operandos é a pegadinha número 1

O primeiro pop é o operando da direita; o segundo é o da esquerda. Para 8 3 -, faça segundo − primeiro = 8 − 3 = 5. Se inverter, obtém −5 e perde a questão. Vale para - e /.

PostfixEvaluator.java — trecho central
for (String token : tokens) {
    if (token.length() == 1 && "+-*/".contains(token)) {
        long right = stack.pop();       // primeiro pop = direita
        long left = stack.pop();        // segundo pop = esquerda
        long result;
        switch (token.charAt(0)) {
            case '+': result = left + right; break;
            case '-': result = left - right; break;
            case '*': result = left * right; break;
            case '/':
                if (right == 0) {
                    throw new ArithmeticException("Divisão por zero");
                }
                result = left / right;
                break;
            default:
                throw new IllegalArgumentException("Operador inválido: " + token);
        }
        stack.push(result);
    } else {
        stack.push(Long.parseLong(token));
    }
}
return stack.pop();

Resultado: 4. A expressão equivale a (6 − (2×3)) + 4.

06 Aplicação 3: infixa → pós-fixa

A conversão usa uma pilha de operadores e uma saída. Regras simplificadas (operadores + − * /, sem parênteses):

ℹ️
O Convert do repositório não é o algoritmo clássico

O arquivo Convert.java do professor apenas separa os caracteres de posições pares e ímpares em duas pilhas e remonta a expressão; ele não implementa precedência nem parênteses. A regra abaixo é a conversão clássica (shunting-yard) que a prova costuma pedir. Não confunda os dois: o Convert do repo é um exercício de pilha, não um conversor geral.

  1. Operando → vai direto para a saída.
  2. Operador → enquanto o topo tiver precedência maior ou igual, desempilhe para a saída; depois empilhe o novo.
  3. Fim → desempilhe todo o resto para a saída.

Precedência: * e / (2) vêm antes de + e − (1).

No −, desempilha * e + (precedências ≥) antes de empilhar o −. Resultado: ABC*+D-.

ℹ️
Com parênteses

Ao encontrar (, empilhe. Ao encontrar ), desempilhe para a saída até achar o ( e descarte-o. O restante é igual. Se a prova pedir só uma expressão simples, a tabela acima já cobre.

07 Onde mais se usa pilha

↩️ Undo/redo

Cada ação é empilhada; desfazer remove a mais recente.

🧮 Chamadas de função

A call stack guarda retorno e variáveis locais; recursão usa pilha.

🧭 DFS / backtracking

Explorar um caminho e voltar é naturalmente LIFO.

🌐 Histórico do navegador

“Voltar” desempilha a página mais recente.

🧩 Validar HTML/XML

Tags abrem e fecham na ordem inversa, como parênteses.

🔁 Inverter ordem

Empilhar tudo e desempilhar produz a sequência reversa.

08 Exercícios de fixação

1. push(10), push(20), push(30), pop(), pop(). Quais valores saem e o que resta?

Saem 30 e depois 20. Resta o 10 no fundo. Essa é a definição de LIFO.

2. Avalie 5 1 2 + 4 * + 3 -.

1 2 + → 3; pila [5, 3]. 4 * → 3*4 = 12; pila [5, 12]. + → 5+12 = 17. 3 - → 17−3 = 14.

Resultado: 14. Equivale a 5 + (1+2)*4 − 3.

3. Qual é a forma pós-fixa de (A + B) * C?

Os parênteses forçam a soma primeiro: A B + C *. Sem parênteses, A + B * C seria A B C * +. A posição do + muda tudo.

4. A expressão [ ( ] ) está balanceada? Onde falha?

Não. Ao ler ], o topo é (; não casa. O algoritmo retorna falso imediatamente. Mesmo que o restante fechasse, a ordem já foi violada.

5. Com pushes 1, 2, 3, 4 (nesta ordem), a sequência de pops 2, 1, 4, 3 é possível?

Sim: push 1, push 2, pop (2), pop (1), push 3, push 4, pop (4), pop (3). Já 3, 1, 2 não é possível: para tirar 3, 1 e 2 já estão empilhados, e o topo seria 2, não 1.

6. Escreva peek() para a pilha com vetor e explique por que não pode ser O(1) se a pilha for uma lista simples sem descritor.

return (T) data[top]; (checando isEmpty antes). Com vetor, é O(1).

Com lista simples sem descritor, o topo é o último nó; para achá-lo é preciso percorrer a lista, O(n). Com descritor (fim), volta a O(1).
