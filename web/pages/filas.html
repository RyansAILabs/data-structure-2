Filas (FIFO)

Fila é a estrutura do “primeiro que entra, primeiro que sai”. Entra no fim (enqueue), sai pela frente (dequeue). O ponto que mais derruba gente na prova é a fila circular: entender front, rear e count sem confundir cheia com vazia.

~30 min de estudo FIFO fila circular código Java testado

01 O modelo FIFO

FIFO = First In, First Out. A fila tem duas pontas: a frente (onde se remove) e o fim (onde se insere). O elemento do meio não é acessível sem remover os da frente. É uma fila de banco: quem chegou primeiro é atendido primeiro.

└─────┴─────┴─────┘

dequeue() → 10        (a frente anda para o 20)

03 Fila sobre lista encadeada

É a implementação do professor: a fila é uma especialização da lista dupla com descritor. enqueue insere no fim e dequeue remove do início — as duas operações ficam O(1) porque o descritor guarda inicio, fim e size.

Os arquivos linkados nesta página são cópias fiéis do repositório do professor; os blocos de código mostram os mesmos métodos com comentários do guia.

Queue.java — completa
public class Queue<T> extends LinkedLinearList<T> {

    public Queue(int capacity) {
        super(capacity);
    }

    public boolean enqueue(T value) {
        return add(value);            // insere no fim
    }

    public T dequeue() throws OperationFailed {
        return pop();                 // remove do início
    }

    public T peek() throws OperationFailed {
        if (isEmpty()) {
            throw new OperationFailed();
        }
        return get(0);                // frente da fila
    }
}
ℹ️
Por que O(1) nas duas pontas?

Com a lista dupla + descritor, inserir no fim usa fim e remover do início usa inicio, ambos diretos. Se fosse uma lista simples sem descritor, inserir no fim seria O(n), pois precisaria percorrer até o último nó.

04 Fila circular com vetor

A fila circular (CircularQueue.java) é um complemento do guia: o repositório do professor traz a fila sobre lista encadeada; a variante circular é a que mais cai em prova quando o enunciado pede vetor + front/rear.

Se usarmos um vetor comum e apenas incrementarmos a frente, as posições do começo ficam vazias e nunca são reutilizadas. A fila “anda para a direita” até estourar o vetor, mesmo com posições livres atrás. A solução é circular: ao passar do último índice, voltamos ao 0 com o operador módulo. 

capacidade = 5
índice:     0     1     2     3     4
          ┌─────┬─────┬─────┬─────┬─────┐
slots:    │  F  │     │  C  │  D  │  E  │
          └─────┴─────┴─────┴─────┴─────┘
             ▲                 ▲
           rear=1           front=2
     (próxima livre)     (primeiro elemento)

Ordem lógica: C → D → E → F   (dá a volta!)
count = 4 · frente = 2 · rear = 1
  • front = índice do primeiro elemento (o próximo a sair).
  • rear = índice da próxima posição livre (onde o próximo entra).
  • count = quantos elementos existem. Resolve a ambiguidade: com count, cheia é count == capacidade e vazia é count == 0.
  • Avanço: front = (front + 1) % capacidade e rear = (rear + 1) % capacidade.
📝
Sem count, a condição de cheia muda

Se a implementação não tiver count, é comum reservar uma posição vazia e usar (rear + 1) % capacidade == front para “cheia”. Nesse caso a fila só guarda capacidade − 1 elementos. Leia o enunciado: se ele menciona count, use count == capacidade. Se não menciona, provavelmente quer a condição com o espaço reservado.

CircularQueue.java — enqueue e dequeue
public boolean enqueue(T value) {
    if (isFull()) {                     // count == capacidade
        return false;
    }
    data[rear] = value;
    rear = (rear + 1) % data.length;    // dá a volta
    count++;
    return true;
}

public T dequeue() throws OperationFailed {
    if (isEmpty()) {                    // count == 0
        throw new OperationFailed();
    }
    T value = (T) data[front];
    data[front] = null;
    front = (front + 1) % data.length;
    count--;
    return value;
}

05 Onde se usa fila

🖨️ Fila de impressão

Documentos são impressos na ordem de chegada.

⚙️ Escalonamento

Processos prontos esperam a CPU em uma fila (round-robin).

🧭 BFS

Busca em largura usa fila para visitar níveis na ordem correta.

📞 Atendimento

Senhas, call center e buffers de rede preservam a ordem.

🎮 Eventos

Filas de eventos/mensagens processam na ordem de chegada.

📥 I/O

Requisições de disco e rede são enfileiradas.

06 Exercícios de fixação

1. enqueue(A), enqueue(B), dequeue(), enqueue(C). Qual é a ordem final da frente para o fim?

Depois do dequeue sai A; restam B. O enqueue(C) põe no fim: B, C. A frente é B.

2. Fila circular de capacidade 5 com front = 3, rear = 1. Quantos elementos há?

count = (rear − front + capacidade) % capacidade = (1 − 3 + 5) % 5 = 3. Os elementos estão nas posições 3, 4 e 0. Se a implementação usar count, é só ler o campo; a fórmula serve para conferir.

3. Em uma fila circular de capacidade 5, rear = 4. Para onde rear vai após um enqueue?

rear = (4 + 1) % 5 = 0. Ele volta ao início do vetor. O mesmo raciocínio vale para front após um dequeue.

4. Por que a fila circular é melhor que “deslocar todo mundo para a esquerda” a cada dequeue?

Deslocar custa O(n) por remoção, pois todos os elementos andam uma casa. A circular apenas incrementa front com módulo, O(1), e reutiliza as posições liberadas. Também evita o desperdício de espaço do início do vetor.

5. Uma fila circular com count tem capacidade 6 e count = 6. Ela está cheia ou vazia? E se count = 0?

Com count = 6 = capacidade, está cheia. Com count = 0, está vazia. Sem count, front == rear seria ambíguo — por isso o campo count é tão útil.

6. Qual estrutura usar para BFS (busca em largura) e por quê?

Fila. A BFS visita os vértices por níveis: os vizinhos descobertos entram no fim e são processados na ordem em que foram encontrados. Se usasse pilha, viraria DFS.

public boolean isEmpty() { return count == 0; }
