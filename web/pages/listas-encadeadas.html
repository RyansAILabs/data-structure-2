Listas lineares encadeadas

Em vez de um vetor contíguo, cada elemento mora em um nó com o valor e uma referência para o próximo (e, na lista dupla, para o anterior). Você troca o acesso direto por flexibilidade: inserir e remover nas extremidades vira O(1). Na prova, quase tudo se resume a desenhar as setas na ordem certa.

~40 min de estudo nó + next/prev descritor código Java testado

01 O nó e a ideia de encadear

Um nó guarda um valor e uma referência. A lista inteira é conhecida pela referência ao primeiro nó (o início, ou head). O último nó aponta para null, indicando o fim. Os nós não ficam lado a lado na memória: é o ponteiro que cria a sequência lógica. 

início
  │
  ▼
┌──────┬──────┐     ┌──────┬──────┐     ┌──────┬──────┐
│ 10   │ next ├────▶│ 20   │ next ├────▶│ 30   │ null │
└──────┴──────┘     └──────┴──────┘     └──────┴──────┘
                                          ▲
                                   fim ───┘  (se houver descritor)

Se você perder a referência do início, perde a lista inteira. Se sobrescrever um next antes de guardar o restante, os nós seguintes ficam inacessíveis (o famoso “perdi a lista”). Por isso a ordem dos comandos é o coração do assunto.

02 Lista simplesmente encadeada

Cada nó tem apenas valor e next. Só é possível caminhar do início para o fim. As operações no início são O(1); para chegar ao fim ou a uma posição, é preciso percorrer.

Inserir no início

novo.next = início;     // 1) novo aponta para o antigo primeiro
início = novo;          // 2) o início passa a ser o novo

antes:  início → [10] → [20] → null
depois: início → [5] → [10] → [20] → null

Inserir depois de um nó p

novo.next = p.next;     // 1) salva o restante da lista
p.next = novo;          // 2) só então liga p ao novo

antes:   [10] → [20] → [30]        (p = nó 10)
depois:  [10] → [15] → [20] → [30]
🚨
A ordem inversa perde a lista

Se fizer p.next = novo primeiro, a referência para o 20 é sobrescrita e o restante ([20] → [30]) fica inacessível. Na prova, escreva sempre novo.next = p.next antes de p.next = novo.

Remover o primeiro

início = início.next;              // pula o primeiro nó
if (início == null) fim = null;    // a lista ficou vazia
size--;

antes:  início → [10] → [20] → null
depois: início → [20] → null

Remover um nó do meio

Na lista simples, você precisa do anterior: anterior.next = alvo.next. Sem a referência ao anterior, é necessário percorrer a lista para descobri-lo — O(n). 

antes:   [10] → [20] → [30] → [40]
remover:               ▲ alvo
operação: anterior(20).next = alvo.next(40)
depois:  [10] → [20] → [40]

03 Lista duplamente encadeada e descritor

Cada nó ganha um prev. Isso permite andar nos dois sentidos e remover um nó conhecido em O(1), pois o anterior está acessível sem percorrer. O custo é um ponteiro extra por nó. 

        ┌──────┬──────┬──────┐        ┌──────┬──────┬──────┐
null ◀──┤ prev │ 10   │ next ├───────▶┤ prev │ 20   │ next ├──▶ null
        └──────┴──────┴──────┘        └──────┴──────┴──────┘

O descritor é um objeto que guarda size, inicio e fim. Sem ele, descobrir o tamanho ou inserir no fim exigiria percorrer a lista. Com ele, essas operações ficam O(1) — e é exatamente o que o código do professor faz. 

        ┌──────────────────────────────┐
        │ Descritor                    │
        │ size = 3                     │
        │ inicio ─────────┐            │
        │ fim ──────────┐ │            │
        └───────────────┼─┼────────────┘
                        │ │
        ┌───────────────▼─▼──────────┐
        │ [10] ⇄ [20] ⇄ [30]         │
        └────────────────────────────┘

Inserir no meio (entre anterior e próximo)

novo.prev = anterior;       // 1) o novo conhece os dois vizinhos
novo.next = proximo;
anterior.next = novo;       // 2) os vizinhos passam a apontar para o novo
proximo.prev = novo;

Nas extremidades, os vizinhos que não existem viram null e o descritor é atualizado: inserir no início muda inicio (e fim, se a lista estava vazia); inserir no fim muda fim. Sempre incremente size.

Remover um nó x

x.prev.next = x.next;    // 2) o anterior pula para o próximo
x.next.prev = x.prev;    // 3) o próximo volta para o anterior

Se x era o primeiro: inicio = x.next;   (x.prev == null)
Se x era o último:   fim = x.prev;      (x.next == null)
size--;
x.prev = x.next = null;  // opcional: isola o nó removido
⚠️
Sempre trate os casos de borda

Antes de acessar x.prev.next ou x.next.prev, verifique se prev/next não são null. Lista vazia, um único elemento, remover o primeiro e remover o último são os casos que mais aparecem em prova — e os que mais quebram código.

04 Monte a lista passo a passo

Use o valor e a posição para inserir/remover e observe o encadeamento. A seta entre nós é o next; o último aponta para null. Repare que a posição de inserção aceita 0..size (inserir no fim é válido).

05 Código essencial

Primeiro a lista simples (arquivo SimpleLinkedList.java). O descritor é representado por três campos: inicio, fim e size. Essa classe é um complemento didático do guia: o repositório do professor implementa a lista dupla com descritor, mostrada logo abaixo. Os arquivos linkados são cópias fiéis; os blocos abaixo mantêm a mesma lógica, com comentários do guia.

SimpleLinkedList.java — inserir e remover
public boolean insert(int position, T value) {
    if (isFull() || position < 0 || position > size) {
        return false;
    }

    SimpleNode<T> newNode = new SimpleNode<>(value);

    if (position == 0) {
        newNode.setNext(inicio);
        inicio = newNode;
        if (size == 0) {
            fim = newNode;
        }
    } else {
        SimpleNode<T> previous = nodeAt(position - 1);
        newNode.setNext(previous.getNext());   // salva o resto
        previous.setNext(newNode);             // só então religa
        if (newNode.getNext() == null) {
            fim = newNode;                     // inseriu no fim
        }
    }

    size++;
    return true;
}

public T remove(int position) throws OperationFailed {
    if (position < 0 || position >= size) {
        throw new OperationFailed();
    }

    SimpleNode<T> removed;
    if (position == 0) {
        removed = inicio;
        inicio = inicio.getNext();
        if (inicio == null) {
            fim = null;
        }
    } else {
        SimpleNode<T> previous = nodeAt(position - 1);
        removed = previous.getNext();
        previous.setNext(removed.getNext());
        if (removed == fim) {
            fim = previous;
        }
    }

    removed.setNext(null);
    size--;
    return removed.getValue();
}

Agora a lista dupla com descritor, que é a versão do repositório (LinkedLinearList.java). O ponto central é inserir usando as extremidades quando possível e atualizar os dois sentidos:

LinkedLinearList.java — insert
public boolean insert(int position, T value) {
    if (isFull() || position < 0 || position > descritor.getSize()) {
        return false;
    }

    Node<T> newNode = new Node<>(position, value);

    if (position == 0) {                       // início
        newNode.setNext(descritor.getInicio());
        if (descritor.getInicio() != null) {
            descritor.getInicio().setPrev(newNode);
        }
        descritor.setInicio(newNode);
        if (descritor.getSize() == 0) {
            descritor.setFim(newNode);
        }
    } else if (position == descritor.getSize()) {   // fim: O(1) pelo descritor
        newNode.setPrev(descritor.getFim());
        descritor.getFim().setNext(newNode);
        descritor.setFim(newNode);
    } else {                                    // meio
        Node<T> previous = nodeAt(position - 1);
        Node<T> next = previous.getNext();
        newNode.setPrev(previous);
        newNode.setNext(next);
        previous.setNext(newNode);
        if (next != null) {
            next.setPrev(newNode);
        }
    }

    descritor.setSize(descritor.getSize() + 1);
    return true;
}
LinkedLinearList.java — remove e nodeAt
public T remove(int position) throws OperationFailed {
    validatePosition(position);
    Node<T> node = nodeAt(position);
    Node<T> previous = node.getPrev();
    Node<T> next = node.getNext();

    if (previous == null) {          // era o primeiro
        descritor.setInicio(next);
    } else {
        previous.setNext(next);
    }
    if (next == null) {              // era o último
        descritor.setFim(previous);
    } else {
        next.setPrev(previous);
    }

    node.setPrev(null);
    node.setNext(null);
    descritor.setSize(descritor.getSize() - 1);
    return node.getValue();
}

private Node<T> nodeAt(int position) {
    if (position < 0 || position >= descritor.getSize()) {
        throw new IndexOutOfBoundsException("Posição inválida: " + position);
    }
    Node<T> current;
    if (position < descritor.getSize() / 2) {   // mais perto do início
        current = descritor.getInicio();
        for (int i = 0; i < position; i++) current = current.getNext();
    } else {                                     // mais perto do fim
        current = descritor.getFim();
        for (int i = descritor.getSize() - 1; i > position; i--) current = current.getPrev();
    }
    return current;
}

Note que nodeAt não vira O(1): ele apenas percorre a partir da extremidade mais próxima, reduzindo o trabalho pela metade. A complexidade continua O(n).

Sequencial × encadeada: o resumo que cai

Sequencial

  • Memória contígua e acesso O(1).
  • Deslocamentos ao inserir/remover no início.
  • Capacidade fixa (ou realocação cara).
  • Menos overhead por elemento.

Encadeada

  • Nós espalhados, ligados por ponteiros.
  • Inserir/remover nas extremidades é O(1).
  • Acesso por posição exige percorrer: O(n).
  • Gasta ponteiro(s) por nó; na implementação da disciplina, tem capacidade fixa.
⚠️
A lista encadeada do professor também enche

A LinkedLinearList do ed20262 recebe capacity no construtor e tem isFull(); add/insert retornam false quando size == capacity. Então não responda “lista encadeada nunca enche”: na teoria ela cresce sob demanda, mas nessa classe há limite. Quem enche é o vetor da lista sequencial; a encadeada da disciplina tem limite explícito.

07 Exercícios de fixação

1. Desenhe a lista simples [10] → [20] após insertAtBeginning(5) e depois add(30). 
início → [5] → [10] → [20] → null
depois add(30): início → [5] → [10] → [20] → [30] → null
fim passa a apontar para o nó 30 (se houver descritor).
2. Na lista [10] → [20] → [30], escreva os comandos para remover o 20.

Suponha anterior apontando para o nó 10 e alvo para o 20: anterior.next = alvo.next;. O 10 passa a apontar para o 30. Se alvo fosse o último, o fim viraria anterior.

3. Por que a lista dupla remove um nó conhecido em O(1), e a simples não?

Na dupla, o nó tem prev, então o anterior é acessível direto: x.prev.next = x.next; x.next.prev = x.prev. Na simples, para achar o anterior é preciso percorrer desde o início, O(n) — a menos que você já tenha essa referência.

4. Qual é o custo de add (fim) em uma lista simples sem e com descritor?

Sem descritor: O(n), pois é preciso caminhar até o último nó para descobrir o fim. Com descritor: O(1), pois fim já aponta para o último nó.

5. Ache o bug no código de remoção de uma lista dupla:
x.prev.next = x.next; size--;

Faltou atualizar o sentido de volta: x.next.prev = x.prev; (quando x.next != null). Também é preciso atualizar inicio/fim se x era extremidade e verificar x.prev != null. Sem isso, a lista fica inconsistente e o percurso inverso quebra.

6. O descritor torna get(5) O(1)? Justifique.

Não. O descritor guarda apenas as extremidades e o tamanho. Para chegar à posição 5, ainda é preciso seguir next (ou prev) nó a nó. O custo melhora de n para cerca de n/2, mas continua O(n).
