Algoritmos de ordenação simples

Bubble, Insertion e Selection resolvem o mesmo problema de formas diferentes. Na prova, o que importa é saber traçar o vetor, contar comparações e trocas, justificar a complexidade e reconhecer o algoritmo pelo código. É exatamente isso que esta página treina.

~35 min de estudo O(n²) no pior caso in-place código Java testado
🧠
Modelo mental para levar para a prova

Bubble: o maior “borbulha” para o fim, uma posição por passada.
Insertion: você tem um prefixo ordenado e encaixa a próxima carta na mão.
Selection: procura o menor do resto e o coloca na posição atual.

Os três são in-place (usam O(1) de memória extra) e O(n²) no pior caso. As diferenças estão no melhor caso, no número de trocas e na estabilidade.

01 Complexidade em 5 minutos

Big-O descreve como o custo cresce quando o tamanho da entrada n aumenta. Para ordenação, contamos principalmente comparações e trocas (ou movimentações).

NotaçãoSignificadoExemplo típico
O(1)custo constante, não depende de nacessar v[i], push em pilha encadeada
O(log n)a cada passo o problema cai pela metadebusca binária
O(n)visita cada elemento uma vezpercorrer lista, busca linear, melhor caso do Bubble/Insertion
O(n²)para cada elemento, olha (quase) todos os outrosBubble, Insertion e Selection no pior caso

Regra prática para a prova: dois laços aninhados percorrendo n → O(n²). Um laço → O(n). Sem laço, acesso direto → O(1). O melhor caso do Bubble/Insertion é O(n) porque o vetor já está ordenado.

03 Bubble Sort

Compare pares vizinhos e troque se estiverem fora de ordem. Ao final de uma passada, o maior elemento do trecho chegou à última posição. Se uma passada inteira não tiver trocas, o vetor já está ordenado e podemos parar.

O arquivo BubbleSort.java do repositório tem três versões. Os nomes importam: a prova pode pedir “o que faz o sortO2()?”. Os três métodos abaixo estão copiados sem nenhuma alteração de ed20261/Exemplos/Ordenação/BubbleSort.

MétodoO que fazComparaçõesTrocas

sortO()escopo reduzido: currentSize-- a cada passada (o laço começa em 0)158
sortO2()mistura bolha com seleção do mínimo (minLimit); é a mesma ideia da classe MinMaxSort910

BubbleSort.java — sort() (escopo fixo) · cópia fiel do repo
public void sort() {
    boolean changed = true;
    // Otimização: reduz o escopo a cada passada, pois o maior elemento "flutua"
    // para o fim
    int currentSize = this.size;

    while (changed) {
        changed = false;
        for (int i = 0; i < currentSize - 1; i++) {
            if (this.array[i] > this.array[i + 1]) {
                this.swap(i, i + 1);
                changed = true;
            }
        }
    }
}

Repare: o comentário fala em “reduzir o escopo”, mas nesta versão currentSize não muda. Quem reduz é o sortO().

BubbleSort.java — sortO() (escopo reduzido) · cópia fiel do repo
public void sortO() {
    boolean changed = true;
    // Otimização: reduz o escopo a cada passada, pois o maior elemento "flutua"
    // para o fim
    int currentSize = this.size;
    int i = 0;
    int totalTimes = 0;
    while (changed) {
        changed = false;
        for (i = 0; i < (currentSize - 1); i++) {
            if (this.array[i] > this.array[i + 1]) {
                this.swap(i, i + 1);
                changed = true;
            }
        }
        currentSize = currentSize - 1; // limit-- -> limit = limit - 1
        totalTimes += i;
    }
    System.out.println("\n\nArray valido: " + this.validate());
    System.out.println("\n\n\nTotal = " + totalTimes);
}
BubbleSort.java — sortO2() (bolha + mínimo) · cópia fiel do repo
public void sortO2() {
    boolean changed = true;
    // Otimização: reduz o escopo a cada passada, pois o maior elemento "flutua"
    // para o fim
    int currentSize = this.size;
    int i = 0;
    int minLimit = 0;
    int totalTimes = 0;
    int minValueIndex = 0;
    int times = 0;
    while (changed) {
        changed = false;
        minValueIndex = minLimit;
        i = minLimit;
        for (times = 0; i < (currentSize - 1); i++,times++) {
            if (this.array[i] > this.array[i + 1]) {
                this.swap(i, i + 1);
                changed = true;
            }
            if (this.array[i] < this.array[minValueIndex]) {
                minValueIndex = i;
            }
        }
        swap(minValueIndex, minLimit);
        currentSize = currentSize - 1; // limit-- -> limit = limit - 1
        totalTimes += times;
        minLimit = minLimit + 1;
    }

    System.out.println("\n\n\nTotal = " + totalTimes);
}

O sortO2() faz a troca final swap(minValueIndex, minLimit) mesmo quando o trecho já acabou. Com vetor vazio isso estoura (ArrayIndexOutOfBoundsException em swap(0, 0)), e a MinMaxSort tem exatamente o mesmo comportamento. Não é bug de digitação: é o código do repositório.

A 5ª passada ainda faz 1 comparação (par 1 e 2), mas nenhuma troca; a flag encerra o algoritmo. Total: 15 comparações e 8 trocas. Com o sort() (escopo fixo), currentSize não diminui: nesse mesmo vetor seriam 5 comparações por passada × 5 passadas = 25 comparações. O sortO2() (igual à MinMaxSort) faz 9 comparações e 10 trocas. Os três terminam ordenados — o que muda é o custo e o número de trocas.

Complexidade

  • Melhor: O(n) — já ordenado, uma passada e para.
  • Médio/pior: O(n²) — ordem inversa é o pior.
  • Memória extra: O(1).
  • Trocas no pior caso: n(n−1)/2.

Propriedades

  • Estável: sim — só troca quando > (estrito).
  • In-place: sim.
  • Parada antecipada: sim, com a flag.
  • Quando aparece: didático e vetores quase ordenados.

04 Insertion Sort

Funciona como organizar cartas na mão: o prefixo 0..i−1 já está ordenado; você pega a “carta” da posição i (chamada aux no repositório), abre espaço deslocando os maiores para a direita e a encaixa no lugar certo. O prefixo cresce até cobrir o vetor inteiro. 

i=1, key=3:   [5 | 3  8  1  9  2]   5 > 3 → desloca 5, encaixa 3
              [3  5 | 8  1  9  2]
i=2, key=8:   [3  5  8 | 1  9  2]   5 ≤ 8 → já está no lugar
i=3, key=1:   [3  5  8  1 | 9  2]   8,5,3 > 1 → deslocam; 1 vai para o início
              [1  3  5  8 | 9  2]
i=5, key=2:   [1  3  5  8  9 | 2]   9,8,5,3 > 2 → deslocam; 2 entra após o 1
              [1  2  3  5  8  9]
InsertionSort.java — sort() · cópia fiel do repo
public void sort() {
    System.out.println(this.toString());
    for (int i = 1; i < this.size; i++) {

        int aux = this.array[i];
        int j = i;

        while ((j > 0) && (this.array[j - 1] > aux)) {
            this.array[j] = this.array[j - 1];
            j -= 1;
            System.out.println(toString());
        }
        this.array[j] = aux;

    }
}

O System.out.println dentro do laço faz parte do código do professor: ele imprime o vetor a cada deslocamento. A lógica é a mesma da versão didática; a diferença é que aqui a comparação é estritamente >, o que preserva a estabilidade.

⚠️
Cuidado com o sinal

Use array[j] > key (estrito) para manter a estabilidade: elementos iguais não são deslocados, então a ordem relativa entre eles é preservada. Se usar >=, o algoritmo deixa de ser estável.

Os números conferem com codigo/InsertionSortMetrics.java (cópia instrumentada; o InsertionSort.java do repo não tem contadores e imprime o vetor a cada deslocamento). Note que o prefixo ordenado não significa “posição final”: o 8 estava no prefixo e depois andou para a direita.

Complexidade

  • Melhor: O(n) — cada chave para após 1 comparação.
  • Médio/pior: O(n²) — muitas inversões.
  • Memória extra: O(1).
  • Movimentações: até n(n−1)/2 deslocamentos.

Propriedades

  • Estável: sim, com comparação estrita.
  • In-place: sim.
  • Parada antecipada: natural, pois o laço interno para cedo.
  • Quando aparece: melhor escolha simples para vetores pequenos ou quase ordenados.

05 Selection Sort

A ideia clássica: a cada posição i, procure o menor elemento do trecho i..n−1 e troque-o com i. A parte esquerda vai ficando definitivamente ordenada. Diferente do Bubble, ele não tem parada antecipada: sempre faz todas as comparações, mesmo que o vetor já esteja ordenado.

O repositório tem três métodos nesse arquivo, e dois deles enganam: sort() é a versão que troca na hora, a cada valor menor que array[y] (correta, mas com mais trocas); sortO1() parece a versão clássica com minIndx, mas não ordena por causa de um bug de comparação; sortO2() é a seleção bidirecional (mínimo e máximo por passada) e ordena. sort() e sortO1() fazem as mesmas n(n−1)/2 comparações; sortO2() faz cerca de metade (em n = 6, 9 em vez de 15). 

Versão clássica (minIndex):
i=0: procura o menor de [5 3 8 1 9 2] → 1 (índice 3)
     troca 5 ↔ 1:  [1 | 3 8 5 9 2]
i=1: menor de [3 8 5 9 2] → 2 (índice 5)
     troca 3 ↔ 2:  [1 2 | 8 5 9 3]
i=2: menor de [8 5 9 3] → 3 (índice 5)
     troca 8 ↔ 3:  [1 2 3 | 5 9 8]
i=3: menor de [5 9 8] → 5 (já está)  [1 2 3 5 | 9 8]
i=4: menor de [9 8] → 8; troca 9 ↔ 8  [1 2 3 5 8 9]
SelectionSort.java — sort() do repositório
public void sort() {
    for (int y = 0; y < size - 1; y++) {
        for (int x = y + 1; x < size; x++) {
            if (array[y] > array[x]) {
                swap(x, y);          // troca a cada valor menor encontrado
            }
        }
    }
}

No vetor [5, 3, 8, 1, 9, 2], essa versão faz 8 trocas (duas por passada nas três primeiras, uma nas duas últimas). A clássica faz apenas 4.

SelectionSort.java — sortO1() (tem bug) · cópia fiel do repo
public void sortO1() {
    int minIndx = 0;
    for (int y = 0; y < size - 1; y++) {
        minIndx = y;
        for (int x = y + 1; x < size; x++) {
            if (this.array[y] > this.array[x]) {
                minIndx = x;
            }
        }
        swap(y, minIndx);
    }
}
🚨
O sortO1() do repositório não ordena

A comparação deveria ser array[x] < array[minIndx], mas o código compara array[y] > array[x]. Como array[y] não muda dentro do laço, minIndx acaba sendo apenas o último elemento menor que array[y], e não o menor do trecho.

Trace [9, 1, 4]: y=0 compara 9>1 (minIndx=1) e 9>4 (minIndx=2); troca 9↔4 e obtém [4, 1, 9]. y=1 compara 1>9 (falso) e para. Resultado final: [4, 1, 9], fora de ordem. Testado no código do repo: falha em 233 de 407 vetores aleatórios.

SelectionSort.java — sortO2() (bidirecional) · cópia fiel do repo
public void sortO2() {
    int lowLimit = 0;
    int highLimit = size - 1;

    while (lowLimit < highLimit) {
        int minIndx = lowLimit;
        int maxIndx = lowLimit;

        for (int x = lowLimit + 1; x <= highLimit; x++) {
            if (this.array[x] < this.array[minIndx]) {
                minIndx = x;
            }
            if (this.array[x] > this.array[maxIndx]) {
                maxIndx = x;
            }
        }
        this.swap(maxIndx, highLimit);
        if (minIndx == highLimit) {
            minIndx = maxIndx;
        }
        this.swap(minIndx, lowLimit);
        lowLimit++;
        highLimit--;
    }
}

O if (minIndx == highLimit) minIndx = maxIndx; existe para o caso em que o mínimo estava justamente na posição do máximo: depois da primeira troca, ele “mudou de lugar”. É a pegadinha dessa variante. Ela ordena corretamente (testado em 400 vetores aleatórios), mas continua O(n²) em comparações.

SelectionSort.java — sortClassic() (correção do guia, NÃO está no repo)
public void sortClassic() {
    for (int y = 0; y < size - 1; y++) {
        int minIndex = y;
        for (int x = y + 1; x < size; x++) {
            if (array[x] < array[minIndex]) {   // aqui está a correção do sortO1()
                minIndex = x;
            }
        }
        if (minIndex != y) {
            swap(y, minIndex);       // no máximo n-1 trocas
        }
    }
}

Essa é a única diferença entre o sortO1() do repo e um Selection correto: comparar array[x] < array[minIndex] em vez de array[y] > array[x]. Se a prova mostrar o sortO1() e perguntar “esse código ordena?”, a resposta é não.

🚨
Selection não é estável — exemplo cobrado em prova

Vetor [3a, 3b, 1]. O menor é 1; o algoritmo troca 1 com a posição 0 (3a): [1, 3b, 3a]. Os dois 3 iguais inverteram a ordem relativa. Por isso o Selection é considerado instável. Se a questão pedir “qual algoritmo escolher para preservar ordem de registros com mesma chave”, não use Selection.

Como isso cai na prova
  • “Mostre o vetor após a 2ª passada do Bubble” → faça uma passada inteira por vez, sem misturar.
  • “Quantas comparações o Selection faz com n = 8?” → 8·7/2 = 28, sempre.
  • “Qual algoritmo escolher se o vetor está quase ordenado?” → Insertion, O(n) na prática.
  • “Qual faz menos trocas?” → Selection clássico, no máximo n−1. O sort() do repositório troca a cada valor menor e pode fazer mais.
  • “Esse sortO1() ordena?” → Não. Ele compara array[y] > array[x] em vez de comparar com array[minIndx]; com [9, 1, 4] termina em [4, 1, 9].
  • “O que é o sortO2()?” → seleção bidirecional (mínimo e máximo por passada). É a mesma ideia da MinMaxSort do Bubble, mas no arquivo do Selection.
  • “Identifique o algoritmo pelo trecho de código” → procure aux (ou key) e deslocamento (Insertion), minIndex (Selection), swap(i, i+1) (Bubble).

07 Exercícios de fixação

Resolva no papel antes de abrir a resposta. O ato de escrever o vetor é o que fixa o algoritmo.

1. Aplique duas passadas completas do Bubble em [4, 2, 7, 1]. Qual o vetor?

Passada 1: 4↔2 → [2,4,7,1]; 4<7 → ok; 7↔1 → [2,4,1,7].
Passada 2: 2<4 → ok; 4↔1 → [2,1,4,7]; 4<7 → ok.

Resposta: [2, 1, 4, 7]. O 7 já está fixo; o restante ainda não.

2. Quantas comparações o Selection Sort faz para n = 8? E quantas trocas, no máximo, na versão clássica?

Comparações = n(n−1)/2 = 8·7/2 = 28, sempre. Na versão clássica (minIndex), trocas ≤ n−1 = 7. O sort() do repositório pode trocar mais, mas continua O(n²) em comparações.

3. Por que o Insertion é O(n) no melhor caso, mas o Selection continua O(n²)?

No Insertion, se o vetor já está ordenado, cada aux é comparada uma vez com o vizinho da esquerda e o laço interno para imediatamente: ~n−1 comparações. O Selection não tem essa saída: para cada posição, ele varre todo o restante para garantir que achou o mínimo, totalizando n(n−1)/2 comparações mesmo com o vetor ordenado.

4. Em um vetor de 6 elementos em ordem inversa, quantas trocas o Bubble faz no total?

Cada par fora de ordem é invertido exatamente uma vez: n(n−1)/2 = 6·5/2 = 15 trocas. Em ordem inversa esse é o pior caso, tanto de comparações quanto de trocas.

5. O trecho abaixo é de qual algoritmo? Justifique.
while (j >= 0 && v[j] > chave) { v[j+1] = v[j]; j--; } v[j+1] = chave;

Insertion Sort. A presença da variável chave e o deslocamento dos maiores para a direita, deixando um “buraco” para encaixar a chave, são a assinatura do Insertion. No Bubble haveria swap(i, i+1); no Selection, minIndex.
