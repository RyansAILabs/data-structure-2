Listas lineares sequenciais

É o bom e velho vetor com um contador. Os elementos ficam lado a lado na memória, sem buracos, nas posições 0..count−1. Você ganha acesso direto O(1); paga com deslocamentos quando insere ou remove no começo/meio. Este é o bloco em que a classe do repositório está com os métodos em branco — aqui ela aparece completa e testada.

~30 min de estudo vetor + count deslocamentos código Java testado

01 O modelo: vetor + count

Uma lista sequencial tem dois campos essenciais: o vetor elements e o contador count. O vetor tem capacidade fixa; o count diz quantas posições estão ocupadas. A primeira posição livre é sempre elements[count]. 

capacidade = 6
índice:    0     1     2     3     4     5
        ┌─────┬─────┬─────┬─────┬─────┬─────┐
vetor:  │ 10  │ 20  │ 30  │ 40  │     │     │
        └─────┴─────┴─────┴─────┴─────┴─────┘
count = 4  ─────────────────┘
isFull() = false      size() = 4      isEmpty() = false
  • count = quantidade de elementos; capacidade = tamanho do vetor.
  • add grava em elements[count] e incrementa count — O(1).
  • get/set usam o índice diretamente — O(1).
  • search percorre do início ao fim — O(n).
⚠️
count ≠ capacidade

Uma lista com capacidade 100 e count 3 tem apenas 3 elementos. Nunca use a capacidade como quantidade de elementos em um for. O laço correto é for (int i = 0; i < count; i++).

03 Inserção: abrir espaço

Para inserir na posição pos, os elementos de pos até count−1 precisam andar uma casa para a direita. O segredo é começar pelo fim; se você começar pelo começo, sobrescreve o próximo antes de copiá-lo. 

Inserir 15 na posição 2 de [10, 20, 30, 40, _, _]

1) elements[4] = elements[3]      [10, 20, 30, 40, 40, _]
2) elements[3] = elements[2]      [10, 20, 30, 30, 40, _]
3) elements[2] = 15               [10, 20, 15, 30, 40, _]
4) count++                        count = 5

Código:  for (int i = count; i > pos; i--) elements[i] = elements[i-1];
SequentialLinearList.java — insert e add
public boolean add(int value) {
    if (isFull()) {
        return false;
    }
    elements[count] = value;   // primeira posição livre
    count++;
    return true;
}

public boolean insert(int position, int value) {
    // posição válida para inserir: 0 .. count (inclusive no fim)
    if (isFull() || position < 0 || position > count) {
        return false;
    }
    for (int i = count; i > position; i--) {
        elements[i] = elements[i - 1];   // abre espaço da direita para a esquerda
    }
    elements[position] = value;
    count++;
    return true;
}

public boolean insertAtBeginning(int value) {
    return insert(0, value);
}
📝
Pegadinha de prova: faixa de posições

insert(pos, v) aceita 0 ≤ pos ≤ count, porque inserir em count é inserir no fim. Já get, set e remove aceitam 0 ≤ pos < count. Se a questão pedir “posições válidas para inserir em uma lista com 5 elementos”, a resposta é 0 a 5, não 0 a 4.

04 Remoção: fechar o buraco

Ao remover a posição pos, guarde o valor antes de sobrescrever. Depois, puxe os elementos seguintes uma casa para a esquerda, do começo para o fim, e decremente count. A última posição deixa de fazer parte da lista. 

Remover a posição 1 de [10, 20, 30, 40, _, _]

removido = elements[1] = 20
1) elements[1] = elements[2]      [10, 30, 30, 40, _, _]
2) elements[2] = elements[3]      [10, 30, 40, 40, _, _]
3) count--                        count = 3
Resultado lógico: [10, 30, 40]
SequentialLinearList.java — remove
public int remove(int position) throws OperationFailed {
    if (position < 0 || position >= count) {
        throw new OperationFailed();
    }
    int removed = elements[position];
    for (int i = position; i < count - 1; i++) {
        elements[i] = elements[i + 1];   // puxa para a esquerda
    }
    count--;
    return removed;
}

public int pop() throws OperationFailed {
    return remove(0);              // nesta disciplina, pop = primeiro
}

public int removeLast() throws OperationFailed {
    return remove(count - 1);
}
🚨
Erro clássico: estourar o vetor

No remove, o laço deve ir até i < count - 1. Se usar i < count, na última iteração você acessa elements[count], que está fora da parte ocupada (e possivelmente fora do vetor). No insert, o laço começa em i = count e vai enquanto i > position; isso é seguro porque elements[count] é a primeira posição livre.

SequentialLinearList.java — campos, construtor e consultas
public class SequentialLinearList {
    private int[] elements;
    private int count;

    public SequentialLinearList(int capacity) {
        if (capacity < 0) {
            throw new IllegalArgumentException("Capacity cannot be negative");
        }
        elements = new int[capacity];
        count = 0;
    }

    public boolean isEmpty()  { return count == 0; }
    public boolean isFull()   { return count == elements.length; }
    public int size()         { return count; }

    public int get(int position) {
        validatePosition(position);
        return elements[position];
    }

    public void set(int position, int newValue) {
        validatePosition(position);
        elements[position] = newValue;
    }

    public int search(int value) {
        for (int i = 0; i < count; i++) {
            if (elements[i] == value) return i;
        }
        return -1;                  // não encontrado
    }

    private void validatePosition(int position) {
        if (position < 0 || position >= count) {
            throw new IndexOutOfBoundsException("Posição inválida: " + position);
        }
    }
}
💡

Não decore a classe inteira. Decore os quatro esqueletos: add, insert, remove e search. Todos cabem em 6 linhas. Na prova, escreva o campo count, valide a posição, faça o laço na direção certa e atualize count. O resto é sintaxe.

06 Vantagens, desvantagens e quando usar

✅ Vantagens

  • Acesso direto por índice em O(1).
  • Memória contígua: boa localidade de cache e menos overhead que ponteiros.
  • Implementação simples e previsível.
  • Percorrer é rápido e sequencial.

❌ Desvantagens

  • Capacidade fixa: pode encher ou desperdiçar memória.
  • Inserir/remover no início ou meio custa O(n) por causa dos deslocamentos.
  • Crescer exige realocar e copiar tudo (quando permitido).
  • Remoções frequentes no início são caras.

Use quando precisa de acesso por índice, o tamanho é conhecido/próximo do máximo e as inserções/remoções acontecem principalmente no fim. Evite quando o padrão é inserir/remover no início (aí a lista encadeada brilha) ou quando o tamanho é muito imprevisível.

07 Exercícios de fixação

1. Lista [7, 8, 9] (capacidade 6). Mostre o vetor após insert(1, 99).

Desloca 9 (índice 2→3) e 8 (1→2); grava 99 em 1. Resultado lógico: [7, 99, 8, 9]; no vetor, count passa de 3 para 4.

2. Lista [10, 20, 30]. Após remove(0) e add(5), qual é o conteúdo?

remove(0) remove 10 e puxa 20 e 30: [20, 30]. add(5) grava na primeira posição livre (índice 2): [20, 30, 5]. Note que o 5 entra no fim lógico, não em ordem.

3. Escreva removeLast() usando remove().

public int removeLast() throws OperationFailed { return remove(count - 1); }. Se a lista estiver vazia, count - 1 = -1 e remove lança a exceção de posição inválida.

4. Por que add é O(1) e insertAtBeginning é O(n)?

add grava direto em elements[count]. Já insertAtBeginning precisa deslocar todos os count elementos uma casa para a direita, e isso cresce linearmente com n.

5. Ache o erro: for (int i = position; i < count; i++) elements[i] = elements[i+1];

Quando i = count - 1, o código acessa elements[count], que está fora da parte ocupada (e pode estourar o vetor se count == capacidade). O limite correto é i < count - 1.

6. O que search retorna quando o valor não existe? E quando existe?

Retorna −1 se não encontrou e o índice da primeira ocorrência se encontrou. Se houver repetições, uma busca do início encontra a primeira.
